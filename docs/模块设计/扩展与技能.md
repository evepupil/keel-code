# 扩展与技能

- **模块定位**：受控打开 pi 的扩展 / skills 加载器，加上默认集、用户自装、项目开关与能力打标。MCP 客户端仍在 [MCP](MCP.md)；本模块管「pi 进程内扩展 + SKILL.md」。
- **对应代码**：待建 `packages/extensions/`（清单、锁版本、加载顺序、能力打标、安装）；引擎 `session/manager.ts` 的 ResourceLoader；CLI `commands/ext.ts`；服务端 `routes/extensions.ts`；Web 设置页扩展区块。第一刀也可以先放在 `packages/engine/src/extensions/`，稳定后再拆包。
- **所属里程碑**：[M8 — 能力插槽](../roadmap.md#m8)
- **当前状态**：未开始（设计已定，见 [设计/07](../设计/07-能力插槽与扩展.md)）
- **最近更新**：2026-08-17
- **设计依据**：[设计/07](../设计/07-能力插槽与扩展.md)

## 职责与边界

做：

- 决定一次会话加载哪些 pi 扩展、哪些 skills。
- 维护默认集锁版本、用户级 / 项目级已装清单。
- 给已加载工具打能力标签（`search` / `browser` / `lsp` / `rewind`），给闭环和提示词用。
- 扩展加载失败时隔离，不拖垮会话。
- `allowExtra` 校验（必须有理由才加载 extra）。

不做：

- MCP 连接（[MCP](MCP.md)）。
- 强制层判定（[强制层](强制层.md)）——扩展工具照样过钩子。
- 闭环何时强制用浏览器（[闭环编排器](闭环编排器.md)）。
- 审批 UI。

## 结构与数据流

```
.keel/config.json ── allowExtra / reason / disabledDefaults / extra / skills.enabled
~/.keel/defaults.lock.json ── 默认集能力 → 包与版本
~/.keel/extensions.json ── 用户自装清单
~/.keel/pi/extensions|skills ── 实际文件（pi agentDir）
<cwd>/.keel/extensions|skills ── 项目级

         │
         ▼
packages/extensions（或 engine/extensions）
  catalog.ts      默认集 + 已装清单读写
  resolve.ts      纯函数：输入配置 + 清单 → 本会话要加载的扩展路径 / skill 目录
  capabilities.ts 工具名 / 包 id → 能力标签
  install.ts      npm / git / 本地路径装进 ~/.keel/pi 或 .keel/extensions
         │
         ▼
engine SessionService.boot
  ResourceLoader({
    agentDir: ~/.keel/pi,
    noExtensions: false,
    noSkills: !skills.enabled,
    extensionFactories: [createKeelExtension, ...resolvedFactories],
    // 另通过 resources_discover 或 loader 选项挂上 .keel/skills
  })
```

`resolve()` 必须是纯函数，方便单测：关 `allowExtra`、缺理由、`disabledDefaults`、重名覆盖等组合。

## 关键决策

1. **默认集按能力锁，不按永远不变的包名。** 候选包实现时核对；跑不通就换或自写薄封装。
2. **keel 扩展工厂永远排第一**，保住 `tool_call` 单调拒绝。
3. **装上 ≠ 加载。** extra 只在项目打开开关且写了理由后进入会话。
4. **不读 `~/.pi/agent`。** 隔离目录是安全边界，不是风格问题。
5. **skills 默认开**，提示词里写明规范优先；闸在钩子，不靠 skill 自觉。
6. **一个扩展挂了只关它自己。**

## 当前实现

无。引擎现在是：

```
noExtensions: true, noSkills: true, noPromptTemplates: true, noThemes: true,
extensionFactories: [createKeelExtension]
agentDir: ~/.keel/pi
```

模板和主题继续关。扩展和 skills 按本设计打开。

## 验证方式

- `resolve()` 单测：默认关 extra；开了没理由仍不加载 extra；开了有理由加载 extra + 默认集；`disabledDefaults` 去掉对应项；skills 关则不返回 skill 目录。
- 加载隔离：故意给一个抛错的工厂，会话仍能 `prompt`，状态里能看到该扩展 `error`。
- 钩子仍在：extra 注册的 `write` 同类工具，无设计系统时 `guard-frontend` 照样拒（用测试夹具扩展，不依赖真实 npm 包）。
- `keel ext list` / doctor 在临时 home 下测清单读写。
- 默认集四项：实现锁定后各做一次 print 模式冒烟（可标 `it.skip` 在无网 / 无 Chrome 的 CI，本机 `keel ext doctor` 必查）。
