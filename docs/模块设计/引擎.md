# 引擎

- **模块定位**：keel 的发动机封装层。把 pi 内核（`@earendil-works/pi-ai` / `pi-agent-core` / `pi-coding-agent`）包成一个稳定的 `Engine` 接口：会话、消息、事件流、工具、钩子、模型与凭据、端点探测。上层（服务端、对话与名册、闭环）只依赖这个接口，不直接碰 pi。
- **对应代码**：`packages/engine/`
- **所属里程碑**：[M1 — 引擎与最小工作台](../roadmap.md#m1)（审批 / MCP / 压缩策略在 [M5](../roadmap.md#m5)；扩展加载器在 [M8](../roadmap.md#m8)）
- **当前状态**：进行中（M1 主体已落地：会话 / 工具 / 钩子 / 模型 / 探测；真实 provider 冒烟待 key）
- **最近更新**：2026-08-17

## 职责与边界

做：
- 会话生命周期：创建（带系统提示、职责段、模型）、恢复、fork、归档；会话文件落 `~/.keel/sessions/<项目哈希>/<会话id>.jsonl`（沿用 pi 的树状 JSONL 格式，可回放）。
- 消息与事件：发消息（steer / followUp / nextTurn 三种投递）、中止、订阅事件流（文本增量、工具调用开始 / 结束、轮次、压缩、费用）。
- 工具：内置 read / write / edit / bash / grep / find（pi 的 coding tools）+ keel 自定义工具注册（结构化 schema）。
- 钩子：`tool_call`（前置，可拒可改，单调）、`tool_result`（后置，可改）、`before_agent_start`（系统提示组装）、`context`（上下文过滤）。
- 模型与凭据：`~/.keel/auth.json` + 环境变量；模型目录（pi-ai 内置 + 用户自定义 OpenAI 兼容端点）；`probeProviders()` 端点探测（连通性、时延、`/models` 列表、单价 / 上下文长度）。
- 自定义会话条目：`appendEntry(type, data)` 持久化 keel 事件（名册、review、验收），不进模型上下文。

不做：对话调度逻辑（对话与名册模块）、闭环（闭环编排器）、HTTP（服务端）、审批 UI（Web）。

## 结构与数据流

```
上层调用 Engine 接口
   │
   ▼
packages/engine/src/
  engine.ts          createEngineHost()（用户级宿主：凭据 / 模型目录 / 设置一份）+ createEngine()（一个项目一个）
  session/           会话创建/恢复/fork、SessionManager 封装、路径规则
  tools/             pi coding tools 装配 + keel 工具注册 + schema 校验
  hooks/             钩子总线：tool_call（单调拒绝）/ tool_result / before_agent_start / context
  models/            模型目录、凭据、providers 探测（probeProviders）
  events/            事件类型定义与转发（对外统一事件流）
  index.ts
```

一条对话 = 一个 pi `AgentSession` 实例；服务端进程内可同时持有 N 个实例（主对话 + 各对话 + 运行中的子 agent）。

## 关键决策

1. **只暴露 `Engine` 接口**：所有 pi 类型不外泄，换引擎（OpenCode 服务端 / 执行器）时上层不动。
2. **会话存储沿用 pi 格式**：不自造格式，换取 fork / 回放 / 压缩免费；keel 数据用自定义条目追加。
3. **钩子单调**：`tool_call` 有一个拦截者说不，就是不；后续钩子只能追加原因不能翻转。
4. **端点探测是引擎能力**：模型选择依赖它，放引擎层而非上层。

## 当前实现

`packages/engine/src/`：
- `types.ts`：对外接口与类型（Engine / EngineSession / 事件 / 消息 / 工具 / 钩子 / 探测），零 pi 类型外泄。
- `paths.ts`：`resolveHomePaths(homeDir)`（用户级：`~/.keel` 下 `auth.json` / `models.json` / `settings.json` / `pi/` / `sessions/`）与 `resolveKeelPaths(cwd, homeDir)`（再加项目级 `sessions/<项目名-哈希>/` + index.json）；`importPiCredentials()`——默认用户目录首次启动时把 `~/.pi/agent/auth.json` 里 keel 没有的 provider 凭据导入（自定义 homeDir / KEEL_HOME 不导，避免测试误用真 key）。
- `hooks/bus.ts`：钩子总线，`tool_call` 单调拒绝、按会话作用域生效、工具注册按作用域下发。
- `models/catalog.ts`：`~/.keel/models.json` 读写（不含密钥）；`models/catalog-service.ts`：设置页添加 / 编辑 / 删除提供方——写盘后 `registerProvider` 同步进进程内 ModelRuntime，密钥仍走 `setRuntimeApiKey`。拉远端模型时带上已保存的密钥；表单地址若还是官方默认，改走目录里用户改过的端点。`list` / `available` / 默认模型只认目录里勾过的（没加提供方、或没勾，都不进选择器）。
- `models/probe.ts`：`probeProviders()`——按 api 类型拼 `/models` 请求（anthropic：`/v1/models` + `x-api-key`；openai 系：`/models` + Bearer），测时延，与目录合并标记 `listedByEndpoint` / `catalogKnown`；HTTP 401/403 时 `reachable` 仍为 true（端点活着）但标记 `authFailed`（凭据不可用），供选档器跳过。
- `session/bridge.ts`：keel 钩子 → pi 内联扩展（`tool_call` / `tool_result` / `before_agent_start`）；keel 工具 → pi `defineTool`（isError 用抛错表达）。
- `session/manager.ts`：`SessionService`——create / open / fork / list，`DefaultResourceLoader`（关掉用户级扩展 / skills / 模板 / 主题，只挂 keel 扩展，`systemPrompt` 由上层传入），`createAgentSession` 后 `bindExtensions({ mode: "print" })`；显式工具白名单要连同 keel 工具名一起给（否则自定义工具不可见——已踩坑）。
- `session/session.ts`：`KeelSession`——prompt（流式中自动 followUp）/ 事件转发 / 消息与用量 / 换模型 / 自定义条目 / meta 更新（写 `keel/meta` 条目 + 索引）。
- `session/index-store.ts`：项目会话索引 `index.json`（丢了从 jsonl 的 `keel/meta` 条目重建），记录消息数 / 最近活动 / 累计费用 / token 用量（input / output / cacheRead）。`updateMeta` 合并 `extra`（置顶等写在 `extra.pinned`）。
- `settings.ts`：`~/.keel/settings.json`（modelLocks / modelTiers / modelDisabled / preferred / kindTiers / cacheTtlMs / acceptance），`engine.settings.get/update`（每次读盘，多引擎共享一致）。
- `engine.ts`：`createEngineHost({ homeDir?, allowModelNetwork? })` → `EngineHost { home, models, settings, createEngine({ cwd }), dispose }`——一个进程一份 pi `ModelRuntime`（凭据 / 模型目录），多个项目引擎共享，任一引擎 setApiKey 全体可见；`createEngine({ cwd, host? })` 给了 host 就在宿主上建，否则自建私有宿主随引擎释放（单项目用法不变）。
- 系统提示随会话持久化（`keel/system-prompt` 条目），open / fork 时恢复；同名工具在都带作用域时允许并存（子 agent 的一次性 `submit_result`）。
- `session/convert.ts`：pi 消息 / 事件 → 引擎消息 / 事件。

pi 版本锁定 `0.84.2`（`@earendil-works/pi-coding-agent` / `pi-ai` / `pi-agent-core`），要求 Node ≥ 22.19。

## 验证方式

`packages/engine/src/**/*.test.ts`（29 个用例）：
- 单测：钩子总线（单调拒绝 / 作用域 / 改参 / 退订 / 链式系统提示 / 工具注册重名）、路径规则、探测请求拼装与响应解析、消息转换、索引重建、`models/catalog.test.ts`（Provider ID 校验、upsert 合并、密钥不落盘）。
- 端到端（`engine.test.ts`，testkit 的 mock OpenAI 服务）：建会话 → 自定义工具执行 → 守卫拦截 `write` 并回流原因 → 正常 `write` 落盘 → 文本收尾 → 事件流（文本增量 / 工具执行 / idle）→ 系统提示与工具进入请求 → 自定义条目与 meta 持久化 → 新引擎实例重开恢复 → 端点探测可达 → 添加 / 拉远端模型 / 删除自定义提供方。
