# 测试工具

- **模块定位**：让整套系统不依赖真模型也能回归：Mock provider（脚本化 / 录制回放）、无头闭环测试夹具、临时项目目录夹具。也是 M0 门禁的落点（`pnpm gate` = lint + typecheck + test）。
- **对应代码**：`packages/testkit/`；根 `vitest.config.ts`、`biome.json`、`package.json` scripts
- **所属里程碑**：[M0 — 项目初始化](../roadmap.md#m0)
- **当前状态**：进行中（门禁 + Mock OpenAI 服务 + 夹具已落地）
- **最近更新**：2026-08-17

## 职责与边界

做：Mock provider（按脚本返回文本 / 工具调用序列；可录制真实响应回放）；`withTempProject()` 夹具（初始化 git 仓库、写入设计系统标志文件等场景）；无头驱动器（创建对话 → 发消息 → 收集事件 → 断言）。不做：业务逻辑。

## 结构与数据流

```
packages/testkit/src/
  mock-provider/   脚本化响应、录制 / 回放
  fixtures/        临时项目目录、git 初始化、常见文件场景
  headless/        无头驱动器与断言辅助
```

## 关键决策

1. **Mock provider 走引擎的 provider 注册口**，不打补丁：测试与生产同一条管线。
2. 门禁三件套用根脚本统一（`pnpm gate`），每个包只声明 `typecheck` / `test`。

## 当前实现

- 根门禁：Biome 2.5（含 Tailwind 指令解析）/ TypeScript 7 `tsc -b` 项目引用（web 单独 `tsc --noEmit`）/ vitest 4 `projects`，`resolve.alias` 把 `@keel-code/*` 指向各包 `src/index.ts`（测试跑源码不依赖 dist）。
- `mock-openai-server.ts`：`startMockOpenAIServer()`——`GET /v1/models`、流式 `POST /v1/chat/completions`，脚本队列 `enqueue()` 或按请求动态 `onRequest()`，记录全部请求（消息 / 工具 / 头）。
- `fixtures.ts`：`makeTempDir()`、`makeTempProject({ git, files })`、`makeTempKeelHome({ baseUrl, models })`（写 pi 格式 `models.json`，provider id `mock`，api `openai-completions`）。
- 根 `scripts/serve-mock.ts`：mock 模型 + keel 服务 + Web 产物，供目验 / 演示。

## 验证方式

`pnpm gate` 全绿（2026-08-17：12 个测试文件 42 个用例）。
