# 文档管理

- **模块定位**：设计文档的确认闭环（打开可编辑视图 → 批注 → 读 diff → 回显理解 → 冻结）、文档修剪 job（提交后兜底：补漏、去重、删过期、维护一致性）、roadmap / 模块文档解析（给看板与门禁用）。
- **对应代码**：`packages/docs/`
- **所属里程碑**：[M4 — 设计确认与看板](../roadmap.md#m4)（文档修剪 job 在 [M5](../roadmap.md#m5)）
- **当前状态**：未开始（M0 仅骨架）
- **最近更新**：2026-08-17

## 职责与边界

做：批注块规范（`> [!批注] …`）的生成与解析；文档 diff 摘要（给 agent 回显理解用）；冻结标记写入（「设计已确认 · 冻结版本 · commit/时间」）；roadmap 表格解析（里程碑、状态、链接）；模块文档头部解析；文档修剪 job（触发时机：提交后；执行者：clean 子 agent，任务模板在方法论包）。

不做：编辑器界面（Web）；产品决定（修剪只整理不创造）。

## 结构与数据流

```
Web 编辑器保存 docs/模块设计/X.md（含批注块）
   │
   ▼
docs/annotations/parse.ts ── 提取批注 + git diff 摘要 ──▶ 交给对话：逐条回显理解
   │ 用户确认
   ▼
docs/freeze.ts ── 写冻结标记 → 提交
提交后 ── docs/prune/job.ts ── clean 子 agent 按模板检查并补全文档

packages/docs/src/
  annotations/   批注块生成 / 解析、diff 摘要
  freeze/        冻结标记
  roadmap/       roadmap 与模块文档解析（看板数据）
  prune/         文档修剪 job
```

## 关键决策

1. **文件为准**：批注、冻结、修剪全部落 markdown，不建数据库。
2. **回显确认的是解释**，防「批了 → 误解了 → 回头改误解」的循环。
3. **修剪 job 只整理不决策**，冲突交主对话。
