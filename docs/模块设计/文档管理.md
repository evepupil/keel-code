# 文档管理

- **模块定位**：设计文档的确认闭环（打开可编辑视图 → 批注 → 读 diff → 回显理解 → 冻结）、文档修剪 job（提交后兜底：补漏、去重、删过期、维护一致性）、roadmap / 模块文档解析（给看板与门禁用）。
- **对应代码**：`packages/docs/`
- **所属里程碑**：[M4 — 设计确认与看板](../roadmap.md#m4)（文档修剪 job 在 [M5](../roadmap.md#m5)）
- **当前状态**：进行中（M4 主体已落地：批注块 / 冻结 / 改动读取工具、安全文件 API、roadmap 解析；文档修剪 job 在 M5）
- **最近更新**：2026-08-17

## 职责与边界

做：批注块规范（`> [!批注] …`）的生成与解析；文档 diff 摘要（给 agent 回显理解用）；冻结标记写入（「设计已确认 · 冻结版本 · commit/时间」）；roadmap 表格解析（里程碑、状态、链接）；模块文档头部解析；文档修剪 job（触发时机：提交后；执行者：clean 子 agent，任务模板在方法论包）。

不做：编辑器界面（Web）；产品决定（修剪只整理不创造）。

## 结构与数据流

```
Web 编辑器保存 docs/模块设计/X.md（含批注块）
   │
   ▼
docs/annotations/parse.ts ── 提取批注 + git diff 摘要 ──▶ 交给对话：逐条回显理解
   │ 用户确认
   ▼
docs/freeze.ts ── 写冻结标记 → 提交
提交后 ── docs/prune/job.ts ── clean 子 agent 按模板检查并补全文档

packages/docs/src/
  annotations/   批注块生成 / 解析、diff 摘要
  freeze/        冻结标记
  roadmap/       roadmap 与模块文档解析（看板数据）
  prune/         文档修剪 job
```

## 关键决策

1. **文件为准**：批注、冻结、修剪全部落 markdown，不建数据库。
2. **回显确认的是解释**，防「批了 → 误解了 → 回头改误解」的循环。
3. **修剪 job 只整理不决策**，冲突交主对话。

## 当前实现

`packages/docs/src/`：
- `annotations/blocks.ts`：批注块规范 `> [!批注] <时间>` + `> 正文`；`renderAnnotation` / `insertAnnotationAfterLine`（0 基行号，-1 文末）/ `parseAnnotations`（带上方最近正文作锚点）/ `stripAnnotations`（冻结时清理）。
- `freeze/marker.ts`：`applyFreeze`（一级标题后插入或替换「> 设计已确认 · 冻结版本 <commit> · <时间> · <备注>」，幂等）、`readFreeze`。
- `roadmap/parse.ts`：`parseRoadmap`（标题、目标、六列里程碑表，链接保留文本与路径）。
- `files/safe-path.ts`：`resolveInside`（越界拒绝）、`isWritableDocPath`（只允许 docs/ 与 .keel/ 下的 md / json）、`readDoc` / `writeDoc` / `listDocs`。
- `files/git-diff.ts`：`fileDiff`（相对 HEAD，`core.quotepath=off`，未跟踪文件用 `--no-index`）、`shortHead`。
- `tools/register.ts`：`keel_design_confirm`（写 `keel/design-confirm` 条目 → UI 弹「设计待确认」卡片）、`keel_doc_changes`（批注块 + diff + 下一步指引）、`keel_design_freeze`（清理批注块 + 写冻结标记 + `keel/design-freeze` 条目）。

服务端：`routes/docs.ts`（`GET /docs`、`GET /docs/read?path&diff=1`、`PUT /docs/write`、`POST /docs/annotate`）、`routes/board.ts`（`GET /board` 聚合 roadmap / review 状态 / 待决策 / 名册；`POST /decisions/resolve`）、`services/docs.ts` 装配工具。强制层：纯文档改动（docs/ .keel/ *.md）的提交豁免 review 与项目门禁。Web：`DocEditor`（CodeMirror 6 markdown、批注对话框、保存、「让 AI 读改动」发消息回对话）、`BoardView`、`DesignConfirmCard` / `DesignFreezeCard` / `AcceptanceCard`。

## 验证方式

- 纯函数单测：`annotations/blocks.test.ts`（插入 → 解析 → 清理往返、多行、文末）、`freeze/marker.test.ts`（插入位置 / 幂等 / 读回 / 无标题）、`roadmap/parse.test.ts`。
- 服务端 `server.test.ts`：写入越界拒绝、写 → 批注 → 读（批注解析、冻结空）、`/board` 聚合。
- 目验（2026-08-17，mock）：主对话调用 `keel_design_confirm` → 卡片「打开批注」→ 编辑器插入批注块 → 「让 AI 读改动」→ AI 用 `keel_doc_changes` 回显理解；看板显示 roadmap 表、review 记录、待决策、名册。
