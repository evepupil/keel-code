# 服务端

- **模块定位**：本地服务进程。持有引擎实例，对 Web 工作台和 CLI 提供 HTTP + WebSocket API：项目、对话、子 agent、事件流、文件（设计文档读写与批注）、git、设置与凭据。只监听 `127.0.0.1`。
- **对应代码**：`packages/server/`
- **所属里程碑**：[M1 — 引擎与最小工作台](../roadmap.md#m1)
- **当前状态**：未开始（M0 仅骨架）
- **最近更新**：2026-08-17

## 职责与边界

做：REST（Hono）+ WebSocket（ws）；项目工作区（一个进程服务一个项目目录，M5 多项目）；对话注册表（内存 + 会话文件扫描）；事件广播（每条对话一个频道 + 全局频道）；文件 API（限项目目录内，供批注编辑器读写 `docs/`）；git 只读查询与提交触发；设置与凭据读写（`~/.keel/`）。

不做：业务规则（对话调度、闭环、门禁在各自包里，服务端只是装配与暴露）；界面。

## 结构与数据流

```
Web / CLI ── HTTP(JSON) ──▶ routes/*  ──▶ services（装配 engine / roster / loop / docs 包）
          ◀─ WebSocket ────  events/broadcast ◀── engine 事件流 + keel 事件

packages/server/src/
  app.ts            创建 Hono 应用、挂路由、启动 ws
  routes/           projects / conversations / agents / files / git / settings / providers
  ws/               连接管理、频道订阅、事件序列化
  services/         对 engine / roster / loop / docs 的装配（组合根）
  auth/             本地令牌（启动时生成，Web 通过 URL 参数取得）
```

## 关键决策

1. **进程内直接持有引擎**，不走 RPC 子进程：单进程简单、事件零拷贝、Windows 少一层进程管理。
2. **一个项目一个进程**（v1）：`keel serve` 在项目目录运行；多项目管理放 M5。
3. **本地令牌**：即使只监听回环地址，也发一个随机令牌防止同机其他页面误连。
