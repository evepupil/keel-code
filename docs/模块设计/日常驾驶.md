- **模块定位**：单会话每天都要用的手感：图、说明书、`@` 钉文件、计划模式、上报前自检、细权限。不新增包，能力拆进现有包。
- **对应代码**：引擎 `session/session.ts`（prompt 带图）；服务端 `routes/sessions.ts`、`hub.ts`（读说明书、拼 attachments）；Web `features/composer/`（回形针、`@`、计划 chip）、`features/chat/ProcessCards.tsx`（计划卡）；方法论 `assemble.ts`；强制层 `config/keel-config.ts` + 审批 `isDangerousCommand`；闭环 `report/orchestrator.ts`（自检）。

## 职责与边界

做：

- 把图和 `@` 钉的文件送进这一轮 prompt。
- 创建会话时读 `MEMORY.md` / `AGENTS.md` / `CLAUDE.md`，交给方法论组装。
- 计划模式的态、拒写钩子、`keel_plan_submit`、计划卡动作。
- 上报前跑类型检查 / 测试。
- 权限 `ask` / `deny` 与内置危险清单。

不做：

- 文件回滚、对话检查点、worktree、后台任务、通知、用户钩子（[并行与安全网](并行与安全网.md)）。
- 浏览器看页面（[扩展与技能](扩展与技能.md) + 闭环挂钩）。
- 设计确认 / 冻结（[文档管理](文档管理.md)）。

## 结构与数据流

```
Web 输入框
  字 + images[] + @attachments[]
         │
         ▼
POST /sessions/:id/prompt
  读附件（安全路径）→ 拼进 text
  图转 ImagePart
         │
         ▼
EngineSession.prompt(text, { images })
         │
         ▼
pi 内核

创建会话
  读 ~/.keel/MEMORY.md + 项目说明书
         │
         ▼
assembleSystemPrompt({ …, manuals, userMemory })

plan 态
  extra.mode = plan
  tool_call：写入 / unsafe bash → 拒
  keel_plan_submit → keel/plan 条目 → 卡
  批准 → extra.mode = act + 执行指令

keel_batch_report
  precheck（typecheck / test）不过 → 打回
  过了 → 再派 reviewer
```

判定函数必须是纯函数：`isDangerousCommand`、`matchPermissionRule`、`shouldPrecheck`、`resolveManuals`。

## 关键决策

1. **图走现有 `ImagePart`**，不自造附件存储。
2. **说明书是参考**，闸和规范优先。不读别人家的 `~/.claude`。
3. **`@` 由服务端读**，不指望模型自己去翻被钉的文件。
4. **计划模式不是冻结**。新模块仍走设计确认。
5. **危险清单在 yolo 之上**；无头模式没有人点卡，危险命令直接拒。
6. **自检失败不派 reviewer**，省一轮。

## 当前实现

无（相对本模块）。相关现状：

- 引擎消息已有 `ImagePart`；`prompt` 只收字。
- Web 回形针 `disabled`。
- `permissions` 只有 `mode` + `allow`。
- 闭环上报直接派 reviewer。
- 系统提示不读 `AGENTS.md`。

## 验证方式

- `resolveManuals()`：缺文件当没有；超 32KB 截断；两份说明书都在就都读。
- `isDangerousCommand()`：`rm -rf /`、`git push --force`、`curl | sh` 命中；`git status` 不命中。
- `matchPermissionRule()`：deny > 危险清单 / ask > mode。
- 计划模式：`write` 被拒、`read` 放行、`git status` 放行。
- 上报自检：故意让 typecheck 失败，不上报不派子 agent（mock）。
- 目验：粘贴一张图问「图上写了什么」；`@` 一个文件问它导出了啥；切计划模式让它改文件，应被拒并交出计划卡。
