# 强制层

- **模块定位**：把最硬的规则焊成引擎钩子：guard-frontend（设计系统未建拦业务页写入）、lint-on-write（写后自动格式化）、commit-gate（无 review-pass 或树指纹不一致拒绝提交；项目自身门禁未过拒绝提交）、审批策略（M5）。全部实现为纯函数 + 钩子适配，逃生舱写在 `.keel/config.json` 且留痕。
- **对应代码**：`packages/guards/`
- **所属里程碑**：[M3 — 闭环编排 + 强制层](../roadmap.md#m3)（审批在 [M5](../roadmap.md#m5)）
- **当前状态**：进行中（M3 三道闸已落地：guard-frontend / commit-gate（review credit + 项目门禁）/ lint-on-write；审批在 M5）
- **最近更新**：2026-08-17

## 职责与边界

做：判定逻辑（给定工具名、参数、项目状态 → 允许 / 拒绝 + 原因）与钩子挂载。不做：review 本身、UI。

## 结构与数据流

```
packages/guards/src/
  frontend/     业务页路径匹配、设计系统标志文件检测（按栈：React / Vue / 原生）
  lint/         写后格式化（prettier / biome 探测）
  commit/       git commit 探测、review credit 核对（树指纹）、项目门禁执行（npm scripts / cargo）
  policy/       审批策略（ask / allow-list / all）（M5）
  register.ts   把上述判定挂到 Engine 的 tool_call / tool_result 钩子，按对话作用域生效
```

## 关键决策

1. **判定与挂载分离**：判定是纯函数，可单测；挂载只做适配。
2. **按对话作用域**：只拦实现阶段的对话，不拦用户手动会话。
3. **单调拒绝**：guard 说不就是不。

## 当前实现

`packages/guards/src/`：
- `config/keel-config.ts`：`.keel/config.json`（`guards.frontend / lintOnWrite / commitGate / projectGate`、`loop`、`acceptance`），缺失或损坏一律回退默认全开；每次钩子触发时读取，改配置即时生效（逃生舱在仓库里可见）。
- `frontend/guard.ts`：`judgeFrontendWrite()` 纯判定——写入类工具（write / edit / str_replace…）+ 业务页路径（pages / views / screens / routes / app 路由页）+ 不在设计系统目录 + 无标志文件（`src/styles/tokens.*`、`src/design-system/*`、`tailwind.config.*` 等）→ 拒绝并给「先建 token + 基础组件」原因。
- `commit/gate.ts`：`judgeReviewCredit()`（无 review-pass 或树指纹不一致 → 拒）；`runProjectGate()`（有 `gate` 脚本只跑它，否则依次 typecheck / lint / test；有 Cargo.toml 再 clippy + test；按锁文件选包管理器；失败返回输出尾部）。
- `lint/on-write.ts`：探测 biome / prettier，写入成功后对该文件格式化（best effort）。
- `register.ts`：`registerGuards()` 把三道闸挂到引擎 `tool_call` / `tool_result` 钩子（作用域 main / conversation / subagent）。

服务端 `services/loop.ts` 与闭环一起装配。

## 验证方式

纯函数单测：`frontend/guard.test.ts`（业务页识别 / 设计系统目录排除 / Windows 反斜杠 / 无设计系统拒 / 组件放 / 建标志后放 / 非写入工具放 / 参数路径提取）、`commit/gate.test.ts`（`git commit` 识别含全局选项 / 无记录拒 / 树不一致拒 / 一致放）。端到端见闭环编排器（提交被拒与放行）。
