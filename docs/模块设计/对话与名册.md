# 对话与名册

- **模块定位**：三层执行单元（对话 / 子 agent / workflow）的运行时实现与名册。主对话工具（探测端点 → 定档 → 创建对话 → 发消息 → 交接 → 归档）、子 agent 工具（clean / fork）、名册 schema / 存储 / 投影 / 新鲜度、复用判据。
- **对应代码**：`packages/roster/`
- **所属里程碑**：[M2 — 多对话与名册](../roadmap.md#m2)（workflow 编排在 [M5](../roadmap.md#m5)，能力档在 [M7](../roadmap.md#m7)，worktree / 后台子 agent 在 [M10](../roadmap.md#m10)）
- **当前状态**：进行中（M2 主体 + M5 workflow 编排 + M7 能力档已落地）
- **最近更新**：2026-08-17
- **设计依据**：[设计/02](../设计/02-对话-子agent与模型选择.md)、[设计/06 能力档](../设计/06-模型档次与多工作区.md)、[设计/09](../设计/09-并行与安全网.md)

## 职责与边界

做：对话注册表与生命周期；主对话 / 普通对话工具集的定义与执行；子 agent 运行器（clean：新会话只带 base + 任务；fork：复制父会话上下文前缀 + 任务；结果作为工具返回值交回）；名册事件（写进对应会话）与仓库投影（`.keel/agents/*.md`）；新鲜度（`last-active-at` vs 缓存 TTL、base-commit、code-hash）；费用累计。

不做：模型探测本身（引擎）、闭环（闭环编排器）。

## 结构与数据流

```
主对话调用 keel_conversation_create({title, role, model, codeRange, initialMessage})
   │
   ▼
roster/conversations/create.ts ── engine.createSession({systemPrompt: base+role, model}) ──▶ 新会话
   │                                    │
   ├── appendEntry('keel/roster', 记录) ─┘
   └── projection/write .keel/agents/<name>.md

keel_agent_run({mode, task, model?, outputSchema?})
   │
   ▼
roster/subagents/run.ts ── clean: engine.createSession(base+task) / fork: engine.forkSession(parent, task)
   └── 等待结束 → 结果回父对话；轨迹持久化并挂在父对话下

packages/roster/src/
  conversations/   create / list / send / read / handoff / archive + 注册表
  subagents/       run（clean / fork）、并发上限、超时
  registry/        名册 schema（zod）、事件读写、投影、新鲜度计算
  models/          能力档选择器（select.ts）；旧的按单价分档 / 锁定辅助（tiers.ts）
  tools/           把上述能力包装成引擎工具（主对话全集 / 普通对话子集）
```

## 关键决策

1. **对话 = 独立引擎会话**，用户可进入；子 agent 一次性，轨迹可查看。两者在数据上都是引擎会话，区别在名册 kind 与 UI 挂载位置。
2. **名册数据两处**：会话事件为主（可回放、冷唤醒后还在）+ 仓库投影为辅（人读、git 版本）。
3. **选模型三步固定**：探测 → 定档 → 启动。AI 只说能力档（轻量 / 标准 / 旗舰），档到具体模型的映射由用户在设置里定，由 `ModelSelector` 查端点通了再落实（确定性代码，不靠 AI 猜）；用户锁定优先于一切；reviewer 取旗舰且尽量与实现者不同。
4. **子 agent 不嵌套**（v1）。

## 当前实现

`packages/roster/src/`：
- `types.ts`：`RosterRecord`（导航字段）、`RosterEntry`（记录 + 状态 + 新鲜度 + 费用）、`ConversationGateway`（由服务端 SessionHub 实现）、`ModelLocks` / `RosterOptions`。
- `registry/record.ts`：记录存放于 `SessionMeta.extra.roster`（随 `keel/meta` 条目持久化 + 进索引，列表不用打开会话）；`mergeRecord`、`rosterFileName`。
- `registry/git.ts`：`currentCommit()`、`codeHash(cwd, globs)`（`git ls-files -s` + `git status --porcelain` 的 sha256 前 16 位）。
- `registry/freshness.ts`：`computeFreshness()` 纯函数——fresh / cache-expired（缓存 TTL 到期）/ code-changed（commit 或指纹变）/ stale（两者都变），带原因文本。
- `registry/store.ts`：`RosterStore`——`entries()` / `entry(id)`（派生条目，状态 idle/busy/archived）、`update(id, patch)`（合并 + 刷新 base-commit / code-hash / summary-version + 写 meta + 重写投影）、`project()`。
- `registry/projection.ts`：`.keel/agents/<标题>-<id8>.md`（表格 + 分节），删除已消失会话的旧文件；`registry/digest.ts`：给主对话看的名册摘要文本（含复用判据提示）。
- `models/select.ts`：**能力档选择器**。`ModelSelector.resolve({ tier, avoid })`：候选 = 已启用（不在 `settings.modelDisabled`）+ 该档（`settings.modelTiers`，缺省 standard）+ provider 最近探测可用（缓存 5 分钟，过期用 5 秒超时复探；网络可达但认证被拒 401/403 同样算不可用；`markUnhealthy` 可让某 provider 冷却）→ 首选（`settings.preferred[tier]`）优先 → 缺档顺位回退（旗舰→标准→轻量；标准→旗舰→轻量；轻量→标准→旗舰）并在 `note` 里说明；`avoid` 只在同档还有别的可选时生效。`overview()` 给设置页 / AI 的三档总览，`renderTierDigest()` 给主对话的档次摘要（替代原来的整张模型表）；`kindTier(settings, kind)` 取各类对话默认档（主对话=旗舰、普通对话=标准、子 agent=标准、reviewer=旗舰、文档修剪=轻量）。
- `models/tiers.ts`：旧的按单价分档（`tierOf`）与锁定辅助（`applyLock`）；`applyLock` 仍用于显式 model / 锁定，`tierOf` 只剩探测表兜底。
- `subagents/run.ts`：`SubagentRunner`——clean（新会话 + 精简方法论 + 任务）/ fork（`engine.sessions.fork` 复制父上下文并继承其系统提示）；模型：显式 `model` > `selector.resolve({ tier: 入参 tier ?? 子 agent 默认档, avoid })` > 继承父会话，结果带 `modelNote`；可选 `outputSchema`（按运行 id 作用域注册 `submit_result` 工具捕获结构化结果）；只读工具集、超时、中止、并发上限；结果 = 最后一条 assistant 文本 + 结构化值 + 费用；子会话 `kind=subagent, parentId=父`，结束后 `extra.subagentFinished`。
- `tools/register.ts`：主对话独有 `keel_providers_probe`（返回档次摘要 + 端点可达性）/ `keel_conversation_create`（收 `tier`；`model` 仅用户点名时传）/ `send / read / handoff / archive`；`keel_agent_run` 与 `keel_workflow_run` 的步骤同样收 `tier`；主对话 + 普通对话 `keel_conversation_list / keel_roster_update / keel_agent_run / keel_tasks_update`（整表覆盖写 `keel/tasks` 会话条目，Web「任务」上拉实时渲染）；普通对话独有 `keel_report_to_main`。
- `workflow/run.ts`：声明式 workflow——步骤（id / task / mode / tier / model / readOnly / dependsOn）拓扑并行（并发上限，默认 3），依赖步骤的结论拼进后续任务，前置失败则跳过；`validateSteps` 校验唯一 / 存在 / 无环；工具 `keel_workflow_run`（主对话 + 普通对话）。

引擎侧配套：`SessionRecord.costUsd`（索引累计费用）、会话系统提示持久化为 `keel/system-prompt` 条目并在 open / fork 时恢复、同名工具按作用域并存（一次性 `submit_result`）、`engine.settings`（`~/.keel/settings.json`：modelLocks / modelTiers / modelDisabled / preferred / kindTiers / cacheTtlMs / acceptance）。服务端：`services/roster.ts` 装配（Hub 充当网关；`ModelSelector` 注入 runner / 工具 / 闭环 reviewer / 文档修剪，并作为 Hub 的默认模型解析器——用户新建对话没指定模型时按 `tier` 或类别默认档落实），`GET /api/roster`、`GET /api/roster/:id`、`GET/PATCH /api/settings`、`GET /api/models/tiers`（三档总览 + 各类默认档 + 探测缓存）。Web：右侧名册面板（新鲜度 / 状态 / 费用 / 记录字段）、非主对话「回主对话」、设置页「模型档次」（每模型分段 轻量|标准|旗舰、启用、★ 首选；三档落点；各类默认档；锁定具体模型收起）、新建对话先选档（chip 显示会落到的模型与单价）再可「指定具体模型…」。

## 验证方式

- 单测：`registry/freshness.test.ts`（四档判定 + 无基准不判变化 + 时长格式）；`models/select.test.ts`（按档落实 + 首选、缺档回退 + 停用 + 不可达跳过 + 认证失败跳过 + 探测缓存、避开实现者、全不可用返回空 + 总览摘要 + 类别默认档）。
- 端到端 `roster.test.ts`（mock 模型驱动主对话）：workflow（a、b 并行，c 依赖两者且拿到其结论）；`keel_providers_probe` 出档位表 → `keel_conversation_create`（选便宜模型、职责进系统提示、`initialMessage` 自动发出、`.keel/agents/前端开发-*.md` 投影含 code-range 与 40 位 base-commit）→ `keel_conversation_list` 含新鲜度 → `keel_agent_run` clean 子 agent（只读工具集、无主对话工具、挂在主对话下、finished=completed）；`store.update` 后改动 code-range 内文件 → 新鲜度变 code-changed。
- 服务端 `server.test.ts`：`/api/roster`、`/api/settings` PATCH 锁定、主对话请求里含 `keel_conversation_create / keel_providers_probe / keel_agent_run` 且不含 `keel_report_to_main`。
- 目验：新建对话后右侧面板显示新鲜 / idle / 费用 / 模型，头部有「回主对话」。
