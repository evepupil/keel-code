# 03 开发闭环与检查点

- **定位**：开发阶段的刚性流程——什么绑死、什么灵活、何时打断用户、review 怎么闭环。状态：已定。最近更新：2026-08-17。

## 标准流程

```
讨论需求 → 模块设计 → 确认设计 → 分批实现 → 自动 review 与修复 → 用户验收 → 下一批
```

## 什么是绑定的（唯一的刚性）

**进入实现后，必定触发：实现 → review → 确定性修复 → 验收简述。** 任何对话进入实现都走这个闭环，不可跳过。

其余一切都是推荐、可选：起不起对话、走不走 design、handoff 与否。用户全拒绝 = 退化成普通 Claude Code + 多了个 review 工作流。这是产品刻意保留的减压阀。

绑定的是**循环**，不是角色——闭环挂在「实现完成」这个事件上，谁实现都触发。机械保证见 [04](04-方法论强制层.md)：不上报就没有 review-pass 记录，提交被门禁拒。

上报前先跑类型检查 / 测试（[M9](../roadmap.md#m9)）：不过就不派 reviewer，省一轮冤枉钱。没有对应脚本就跳过那一项。页面核对应走浏览器挂钩（[M8](../roadmap.md#m8)），不在自检里起 dev 服务器。

## 两类检查点（决定何时打断用户）

- **工程检查点**：目录初始化、设计 token、数据库迁移、测试、静态检查、review 修复。系统自动继续，只记录证据，不打断用户。
- **用户验收点**：只在用户已经能看到效果、能完成业务操作、能判断方案是否符合预期时暂停。

**判据一句话**：用户当前能否给出「符合预期 / 哪里要调」之外的有效反馈？只能回复「继续」的，就不是验收点。代码质量由 reviewer 和门禁负责，**不把代码检查包装成用户验收**。

## 验收节奏

三档可选：及时验收 / 里程碑验收 / 最终验收（全程托管，只在决策、风险、阻塞时打断）。默认档待定（设置项）。

## 设计确认（/confirm）的交互

现有工具的确认做得差（「文档放到 xxx 目录了」，用户打不开，干脆摆烂）。我们的做法：

1. 到确认节点，**Web 端自动打开设计文档的可编辑视图**，用户直接批注、划选、修改（CLI 下给路径和打开命令）。
2. 用户改完示意，AI 读取文档的 git diff。
3. **防误读环节**：AI 把每条改动翻译成具体设计变化，回显「你改的是 X，我理解为要变成 Y，对吗？」逐条确认。
4. 用户确认后落定，标注「设计已确认 · 冻结版本 · commit/时间」。
5. 冻结后才允许实现。后续需求变化只重新确认受影响部分。

前提立场（用户原话）：模块设计**必须**用户确认。「我试过不确认，后期重做头很大。」

轻量计划模式（[08](08-日常驾驶.md)）管的是另一档：修 bug、改一个接口、补测试。只读出方案，用户点头再改代码。**不能当冻结的替身**——新模块、新设计系统、会改数据含义的方案，计划卡里必须有一步走本页的确认，批准执行也不能跳过冻结闸。

## 验收简述的规范

验收时 AI 只简述、让用户自己验：本批完成了什么（业务结果）；在哪看 / 怎么操作；预期结果；本批范围边界（什么没做）。

## review 分类：自动修复 vs 待决策

**自动修复**（答案明确、不需业务取舍）：编译、类型、格式、测试失败；空值、边界、并发、事务、错误处理等确定性缺陷；需求已有明确要求但代码没正确实现；违反项目结构、编码规范或前端设计规范；重复代码、职责混乱、缺少必要测试；已确定视觉方案下的样式偏移。

**待决策**（交用户）：需求存在歧义或互相冲突；实现结果暴露出新的产品选择；修复会改变业务流程、数据含义或验收标准；多种方案都合理，选择影响后续设计；需求本身可能要改。

**分不清属于哪一类时，默认归「待决策」**——宁可多问，不擅自改业务语义。「待决策」不动代码，但问题不能丢：写明冲突、影响范围、可选方案，落 `docs/review/待决策.md`，交主对话集中询问用户。受影响的任务暂停，其他无依赖任务继续运行。

## 修复与复验规则

- reviewer 是 clean 子 agent（干净上下文，不继承实现的漫长尝试）；每轮全新一次性，天然满足「修复不能自证通过」。
- 同一个问题连续修复仍不通过（上限 3 轮）→ 升级为待决策，停下找用户。
- 修复过程中发现模块设计存在根本问题 → 重新打开设计文档走用户确认。
- review 问题必须写入记录（单次快照 + 剩余问题总览，见全局规范 `docs/review/`）。

## 失败与完成

- 验收不通过：**原实现对话**继续修改。
- 模块完成条件（用户原话）：「模块按照设计的全部实现完成了就行了」。

## 中途变化

直接处理，做完更新文档。不做自动标记失效 / 暂停依赖链 / 重排期。
