# 06 模型档次与多工作区

- **定位**：2026-08-17 定稿的两项设计——AI 不再自选具体模型（改为「能力档」）；`keel web` 单实例多工作区。状态：已定，实现中。最近更新：2026-08-17。

## 一、能力档（模型档次）

### 为什么

AI 自选具体模型不稳（按单价猜档位不准、会挑到效果差的模型），而且创建对话前不查端点通不通。改为：**AI 只说要什么档，档到具体模型的映射由用户定、由系统查通再落实。**

### 命名

能力档：**轻量 / 标准 / 旗舰**（`light | standard | flagship`），与推理档（关 / 低 / 中 / 高）彻底错开词。

- 轻量：便宜快——跑测试、批量改名、文档修剪、只读探索
- 标准：默认——普通对话、大多数子 agent
- 旗舰：最强——主对话、reviewer、设计与疑难实现

### 规则

1. 每个模型一个能力档，缺省「标准」；可「停用」；同档内可设「首选」（★），其余按目录顺序兜底。存 `~/.keel/settings.json`：`modelTiers`、`modelDisabled`、`preferred`（各档首选）、`kindTiers`（各类对话默认档：主对话=旗舰、普通对话=标准、reviewer=旗舰、子 agent=标准、文档修剪=轻量）。`modelLocks`（锁定具体模型）优先级最高。
2. AI 工具只收 `tier`（`keel_conversation_create / keel_agent_run / keel_workflow_run`），保留 `model` 给用户显式指定；提示词明确「只说档次，不点名模型」。
3. `resolveModel(tier)` 是确定性代码：候选 = 已启用 + 该档 + provider 最近探测可达 → 首选优先 → 缺档顺位回退（旗舰→标准→轻量；轻量→标准→旗舰；标准→旗舰→轻量）并在结果里说明回退。
4. 探测结果带时间戳缓存；创建前缓存超过 5 分钟就快速复探（5 秒超时）；不通的 provider 的模型不进候选。
5. reviewer 取旗舰，尽量与实现者不同；文档修剪取轻量。
6. 目录不认识的新模型：设置页标「目录未知」，用户「启用并补信息」（上下文长度 / 单价 / 是否推理）后写入 `~/.keel/models.json` 才进候选（第一版先做展示与档位，写入 models.json 后续补）。

### 交互

设置页「模型」：每个已配置 provider 一张卡（可达 / 时延 / 上次探测 / 重新探测），卡内每个模型一行：分段按钮 `轻量 | 标准 | 旗舰`、启用、★ 首选、上下文、单价。下方「档次分配」实时显示每档落到哪个模型、缺档时回退到哪；再下面是各类对话默认档与锁定。「新建对话」与聊天头部的选择器先选档（chip 上直接显示会落到的模型与单价），想钉死再「指定具体模型…」；推理档单独一个小选择。

## 二、多工作区（`keel web`）

### 目标

任意目录 `keel web` → 打开一个包含所有项目工作区的工作台。

### 规则

1. `~/.keel/workspaces.json`：`[{ id, path, name, addedAt, lastOpenedAt }]`。
2. 一个工作区 = 一个 `KeelRuntime`（引擎 + 会话中枢 + 名册 + 闭环 / 强制层 + 文档工具 + MCP + 审批），按需懒启动，长时间无人用自动释放。
3. 路由：全局 `/api/workspaces`（列表 / 添加 / 移除 / 原生选目录）、`/api/providers` `/api/models` `/api/settings`；工作区级全部在 `/api/w/:wid/…`。WebSocket 一条连接复用，订阅与推送都带 `workspaceId`。
4. `keel web [目录]`：读 `~/.keel/web.json`（端口 / 令牌 / pid）探活——活着就注册当前目录为工作区并开浏览器；不活就**后台**起服务（日志 `~/.keel/web.log`），`--foreground` 前台调试，`--stop` 停掉。当前目录不是项目（无 .git 也无 .keel）时只开工作台不注册。`keel serve` 保留为单项目别名。
5. Web：状态按工作区分桶；URL `#/w/<wid>/c/<sid>`、`#/w/<wid>/board`、`#/w/<wid>/doc/<path>`、`#/settings`；顶栏工作区切换器 + 添加工作区（粘路径或原生选目录）；待处理事项跨工作区汇总。

### 顺序

先能力档（影响闭环质量），再多工作区，最后前端整体重构（建立在多工作区的 URL / 状态结构之上）。
