# 04 方法论强制层

- **定位**：规范本体 + 执行机制——规范怎么写、怎么焊成绕不过去的闸。状态：规则已定，载体为 keel 自研引擎层的钩子。最近更新：2026-08-17。

## 分层原理：提示词讲 why，基础设施执法

- **提示词层**（base 方法论 system prompt）：讲规则和「为什么」，指导默认行为。缺点：长上下文下规则优先级会被稀释。
- **强制层**（引擎钩子 / 门禁）：管「绕不过去」。最硬的规则必须在这里兜底。

整个产品的赌注是「下限高、小白绕不过去」，这个保障不能交给 agent 自觉。

## 载体（自研引擎）

强制层全部落在 `@keel-code/engine` 暴露的进程内钩子上：

- `tool_call`（工具执行前）：可拦截并给原因、可改参数、**单调**（一个 guard 拒了，后续插件不能翻转）、可按对话作用域生效（只拦实现阶段的对话，不拦用户手动会话）。
- `tool_result`（工具执行后）：lint-on-write、提交后刷新 review credit。
- `before_agent_start`：系统提示组装（base + 职责 + 名册导航），注入当前约束状态。

每条强制可关（`.keel/config.json`），关闭动作留在仓库里可见。

## 四道闸（前端防积重难返的核心工程）

1. **设计系统 bootstrap（不可跳过）**：写任何业务页前，token（色板、字体配对、间距、圆角、阴影、控件尺寸）+ 基础组件必须先建好。
2. **组件库锁定**：只能用项目组件库 / 设计系统的既有变体，禁止手写轮子。
3. **反模式 lint**：生成完扫描，命中即打回。
4. **真实文案注入**：文案来自需求文档；禁止模板废话；最小必要信息。

## 前端反 AI 味清单（命中即改 / 拦）

- 禁 emoji 当图标；禁 lucide 图标 + emoji 混搭
- 禁紫粉 / 靛蓝渐变，禁渐变文字
- 禁 `rounded-2xl` 铺满全场
- 禁 Inter 单字族孤悬（要字体配对）
- 禁「立即开始 / 赋能你的团队」式空话营销文案
- 颜色、字体、字号、间距、圆角、阴影全部走 token，禁止散落硬编码数值
- 设计系统标志文件不存在时，业务页面写入直接被拦（guard-frontend）

进阶警惕：规则太轴，工具自己会形成可识别的「你的工具味」。目标是让人看不出是哪个工具生成的。

## 通用方法论硬规则

- 按职责拆分到多个目录 / 文件，禁止一坨。
- 模块设计先于代码；设计文档是代码的边界锚点。
- 单一数据源。
- 严格模式全开。
- 核心业务逻辑写单测；纯展示层不写。
- 页面和组件必须考虑：长文本溢出、空状态、加载、错误、自适应。
- 文档体系：roadmap + 模块设计文档 + review 双记录。

## 三道门禁

| 门禁 | 触发 | 规则 |
|---|---|---|
| guard-frontend | 写入类工具命中业务页路径 | 设计系统标志文件不存在 → 拒绝并给原因 |
| lint-on-write | 写入完成后 | 自动格式化；可配置 |
| commit-gate | bash 里出现 `git commit` | ① 必须存在 review-pass 记录且当前工作树指纹一致；② 项目自身门禁（typecheck / lint / test / cargo）通过 |

## 规则颗粒度与逃生舱

- **通用层**：硬执行。**项目层**：初始化时选，选完硬执行。
- 每条硬规则配一个逃生舱 + 一句为什么。当前实现是禁令式，「默认轴 + 逃生舱 + 为什么」拨档是待扩展项。
- 第三方扩展（[07](07-能力插槽与扩展.md)）加进来的工具同样过这三道闸；扩展是进程内代码，存在绕过工具接口的洞——所以 extra 默认关，打开必须写理由。
- 审批在三档之上还有 `ask` / `deny` 规则和内置危险清单（[08](08-日常驾驶.md)）。yolo 也拦危险命令；无头模式没有人点卡，危险命令直接拒。
- 用户钩子（[09](09-并行与安全网.md)）挂在闸和审批都放行**之后**，只能再拒，不能把已经拒绝的改成允许。用户级钩子默认关，打开必须写理由。
