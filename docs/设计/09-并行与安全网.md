# 09 并行与安全网

- **定位**：让人可以同时干几件事、离开屏幕也不慌、改坏了能退回来。状态：已定稿。最近更新：2026-08-17。
- **实现入口**：[模块设计/并行与安全网](../模块设计/并行与安全网.md) · [引擎](../模块设计/引擎.md) · [对话与名册](../模块设计/对话与名册.md) · [服务端](../模块设计/服务端.md) · [Web界面](../模块设计/Web界面.md) · [强制层](../模块设计/强制层.md) · [CLI](../模块设计/CLI.md)
- **所属里程碑**：[M10](../roadmap.md#m10)
- **依赖**：[M5](../roadmap.md#m5)（审批、运行时）、[M8](../roadmap.md#m8)（文件回滚能力、扩展那套「进仓库 + 写理由」的纪律）

## 拍板（2026-08-17）

1. **worktree 并行**：对话可以进自己的 git 副本干活，主工作树不被它踩。默认仍不并行同模块。
2. **对话检查点**：退回到某一轮对话。有 [M8](../roadmap.md#m8) 文件回滚时，可选连文件一起退。两件事不要混成一个按钮说不清。
3. **压缩看得见、压得动**：点用量环看上下文被谁吃掉；能立刻压一轮；能丢掉历史新开一条同职责对话。
4. **后台子 agent**：`keel_agent_run` 可立刻返回，干完再通知。长 shell 能丢后台再聊——只在 pi 内核已经支持时打开，不自造第二套壳。
5. **本机通知**：审批卡住、review / 验收出结果、后台活干完、对话空闲超过一分钟。不做手机远程接管。
6. **用户钩子**：项目里可挂 `pre_tool_use` / `post_tool_use` / `session_end` 的 shell。闸已经拒的，钩子翻不了案。用户级钩子默认关，打开必须写理由。

## 要解决什么

M9 让单会话好开。人一旦认真用，下一档摩擦是：

- 两条对话改同一个仓库，文件互相覆盖；
- 想回到「它还没把那段拆坏」的那一轮，只能口头说「撤销」；
- 上下文环快满了，不知道该压还是该清；
- 跑测试把对话卡住，不能先丢一边；
- 去倒杯水回来，不知道过没过、卡没卡审批；
- 想在提交前自己再跑一道检查，只能写进提示词，长了就被稀释。

这些仍然服务「下限高」：隔离避免小白并行踩踏；检查点避免不会 git 的人救不回来；钩子让团队把约定焊进事件，而不是焊进 prompt。

## 和现有设计怎么相处

| 已有 | 本里程碑加上的 | 谁让谁 |
|---|---|---|
| 「同模块默认串行」（[02](02-对话-子agent与模型选择.md)） | worktree | 串行建议不变。跨模块、或用户明确要隔离时才开副本 |
| M8 `rewind`（退文件） | 对话检查点 | 两个入口。头部「退回上一刀」管文件；消息上「退回这一轮」管对话，可勾选带上文件 |
| pi 自动压缩 | 手动压缩 + 分项占用 | 自动仍在。人能看、能下手 |
| 任务上拉面板 | 后台任务 | 面板里能看见跑着的后台活 |
| `allowExtra` 纪律（[07](07-能力插槽与扩展.md)） | 用户级钩子 | 同一套：默认关、进仓库、写理由、警告原文不能改软 |
| 强制层单调拒绝 | 项目钩子 | 钩子在闸和审批都放行**之后**还能再拒；不能把已经拒绝的改成允许 |

## 六件事

### 1. worktree 并行

一条对话可以绑定一个 git worktree：

- 创建时勾「在隔离副本里做」，或 `keel_conversation_create` 带 `worktree: true`。
- 系统执行 `git worktree add <根>/.keel/worktrees/<会话短 id> -b keel/<短 id>`。会话的 cwd 指到副本。子 agent 继承这份 cwd。
- 主对话、未勾选的对话，继续用项目主工作树。
- 归档对话时，若勾了自动清理（默认开），`git worktree remove` 并删本地分支；未合并的改动先拒绝清理，设置里能看到「有未合入的副本」。
- 合回主仓是对话自己的活（开 PR 或合并），keel 不自动合，避免两套真相。

不做：非 git 仓库的拷贝目录、hook 换 VCS、每个对话默认进副本、一个 worktree 再开一份 `keel serve`（现在这种笨办法仍可用，只是不再是推荐路径）。

Windows 上 git worktree 能用就用；加失败把原因写进创建结果，对话退回主工作树，不把创建整单打挂。

### 2. 对话检查点

每轮用户消息落下后记一个检查点：`{ id, at, messageIndex, label }`，最多留 20 个。

- 消息悬停「退回这一轮」：默认只退对话。
- 本会话加载了 M8 `rewind` 时，多一个选项「连文件一起退」。
- 实现先问 pi 能不能按条目截断当前会话文件。能就原地截；不能就 fork 到检查点再让 UI 切过去，旧会话标成「已从这里退回」并归档。

和 M8 文件回滚的分工写在界面上，不要一个按钮两件事。

不做：跨 `/clear` 式的无限历史考古、按文件 diff 挑着回。

### 3. 压缩与清空

- 点输入框旁的用量环：弹出分项（系统提示、说明书、工具定义、历史消息、skills / 名册，估不准就按字符/4 标「约」）。
- 「现在压缩」：可带一句聚焦（「只留接口改动」），调引擎压缩。已有 `compaction_*` 事件，接上即可。
- 「新开一条、丢掉历史」：归档当前，按同一职责 / 模型 / 代码范围建新对话，名册标它接班。不删文件。

不做：用户自己调自动压缩阈值（继续用 pi 默认，真用过再调，和 M5 同一句话）。

### 4. 后台任务

两层，先做我们能做稳的：

1. **子 agent 后台**：`keel_agent_run({ background: true })` 立刻返回 job id。跑完写 `keel/subagent-done` 条目，WS 推到任务面板。权限请求仍上浮到父对话（沿用现有审批卡）。
2. **长 shell**：若 pi 的 bash 已经能超时转后台，打开它，并在任务面板露出。若没有，本里程碑**不**自造第二套 shell / PTY。

并发上限沿用子 agent 现有上限。主对话被中止时，它拉起的后台子 agent 一并中止。

不做：交互式 PTY、把整条对话丢给 supervisor 进程、跨机器派活。

### 5. 本机通知

什么时候喊：

- 审批卡出现，且当前窗口没在前台；
- review 出结果、验收卡出现；
- 后台活结束；
- 对话空闲超过 60 秒（人可能已经走开）。

怎么喊：Windows 用系统通知（不引原生模块，走系统自带能力）；Web 页在后台时用浏览器 Notification。设置在「通用」：四类开关，默认全开。

不做：手机推送、Remote Control、Slack / IM、抢焦点弹窗。

### 6. 用户钩子

生命周期先做三个：`pre_tool_use`、`post_tool_use`、`session_end`。只要 shell 一种。

```json
{
  "hooks": {
    "allowUser": false,
    "allowUserReason": "",
    "events": {
      "pre_tool_use": [{ "match": "bash", "command": ".keel/hooks/pre-bash.sh" }],
      "session_end": [{ "command": ".keel/hooks/on-end.sh" }]
    }
  }
}
```

规则：

1. **项目钩子**：写在 `.keel/config.json`，进 git。有条目就跑。这是团队自己的 CI，默认信任仓库里的。
2. **用户级钩子**（`~/.keel/hooks.json`）：只有项目打开 `hooks.allowUser` 且写了理由才跑。警告原文与 [07](07-能力插槽与扩展.md) 同一纪律，不要改软——钩子是本机用户权限的 shell。
3. **顺序**：强制层判定 → 审批 → 项目 `pre_tool_use` →（可选）用户 `pre_tool_use`。前面任何一层拒了，后面看不见这次调用。钩子退出码非 0 = 再拒一次；钩子不能放行已经被拒的调用。
4. **超时**：10 秒杀。挂了只记日志，不当成放行。
5. **不读** `~/.claude/hooks`、`~/.pi` 里的脚本。

不做：用模型当钩子（prompt / agent 类型）、HTTP 钩子、任意生命周期 30 个事件。

## 明确不做

- OS 沙箱（seatbelt / bubblewrap / Windows 隔离用户）。Windows 一等公民 + v1 不引原生模块，继续后置。
- Agent Teams、跨会话互发消息、把 keel 当别人的 MCP server。
- 云端会话、手机接管、定时 `/loop`。
- 插件市场、VS Code 扩展、diff 按块接受（形态档，见 [M6](../roadmap.md#m6) 及后置清单）。
- 非 git 的隔离副本。

## 目录与配置

```
<项目>/.keel/
  config.json          # worktree.autoCleanup / hooks / 既有字段
  worktrees/<短 id>/   # git worktree（gitignore 掉）
  hooks/*.sh           # 项目钩子脚本（人写，进 git）

~/.keel/
  MEMORY.md            # M9 的用户说明书，本里程碑不改
  hooks.json           # 用户级钩子清单
  settings.json        # notifications.* 
```

`.gitignore`：`keel init` 补上 `.keel/worktrees/`。

会话：`SessionMeta.extra.worktreePath`；检查点走自定义条目 `keel/checkpoint`，不进模型上下文。

## CLI / Web / 服务端

- **CLI**：`keel doctor` 报 worktree 是否能建、残留未清理的副本、钩子清单、通知是否可发。
- **Web**：新建对话勾隔离副本；消息「退回这一轮」；用量环弹出；任务面板接后台活；通用设置通知四开关。
- **服务端**：创建会话可带 `worktree`；`POST /sessions/:id/compact`、`GET /sessions/:id/context`、`POST /sessions/:id/rewind`；后台 job 列表走任务面板已有通道。
- **无头**：不弹通知；后台子 agent 仍要等它结束再退出（沿用 `keel run` 现有等待）。

## 实现顺序（M10 内）

1. 压缩 + 上下文分项（事件已有，先让人看得见）。
2. 对话检查点。
3. 后台子 agent + 任务面板。
4. 本机通知。
5. worktree。
6. 用户钩子（最后做：纪律和警告文案要对齐 M8）。
