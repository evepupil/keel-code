# 07 能力插槽与扩展

- **定位**：把「别人已经做好的能力」接进来，同时守住 keel 的下限。状态：已定稿。最近更新：2026-08-17。
- **实现入口**：[模块设计/扩展与技能](../模块设计/扩展与技能.md) · [引擎](../模块设计/引擎.md) · [MCP](../模块设计/MCP.md) · [强制层](../模块设计/强制层.md) · [闭环编排器](../模块设计/闭环编排器.md)
- **所属里程碑**：[M8](../roadmap.md#m8)

## 拍板（2026-08-17）

1. **默认集**：搜索、浏览器、代码智能、回滚四项关键能力，随 keel 装进自己的目录，开箱能用。
2. **用户可自装 pi 扩展**；要生效必须在**项目** `.keel/config.json` 里打开开关。开关进仓库 = 留痕；打开时必须给用户看清楚风险。
3. **Skills 开**：加载 SKILL.md（跨工具开放标准），项目目录与 keel 目录都认。
4. **不自动继承**用户机器上的 `~/.pi/agent`（那是 pi 自己的家，装过什么我们管不住）。
5. **不做** dsh / Cordis 适配；Claude Code 插件市场后置（skills / MCP 已经覆盖它的主要内容）。

## 要解决什么

编程工具个人做，生态永远不够。Playwright、上网搜、LSP、回滚这些，市面上已经有现成的。我们要的是插槽，不是每个都自己写一遍。

同时：能力可以借，确定性借不来。别人的扩展不会替我们执行「前端批次必须看一眼页面」「没 review 不能提交」。插槽只解决「有没有这个能力」；「必须用、用完怎么记」仍是 keel 自己的活。

## 三条通道

| 通道 | 装什么 | 生态 | keel 现状 | 本里程碑 |
|---|---|---|---|---|
| **MCP** | 进程外工具（浏览器、搜索、数据库、Figma…） | 官方注册表近万 | 客户端已有（stdio / HTTP） | 补 resources / 提示词、热重载、按对话类型限可见性；设置页能装推荐服务器 |
| **pi 扩展** | 进程内 TypeScript：注册工具、听钩子、加命令 | awesome-pi 索引数千（有水分，能用的是真的） | **刻意关掉了**（`noExtensions: true`，且 `agentDir` 指 `~/.keel/pi`） | 受控打开：默认集 + 用户自装（开关） |
| **Skills（SKILL.md）** | 知识和流程。启动只读 name / description，用到再读正文 | Anthropic 2025-12 开放标准，Claude Code / Codex / Cursor / OpenCode / pi 通用 | `noSkills: true` | 打开。默认目录 + `.keel/skills/` |

pi 自己的定位就是「内核精简，能力靠扩展」。搜索、浏览器、LSP、rewind 社区都有现成包。我们锁了 pi 0.84.2，装扩展等于把别人的兼容问题引进来——所以默认集要锁版本、实现时按 print / Web 模式验过再钉死。

## 明确不做

- **dsh / Cordis 适配**：要跑别人的 dsh 插件就得在 keel 里再造一套 Cordis 上下文。官方还处在 preview，契约会变。dsh 生态里可移植的部分（skills、MCP）走上面两条通道就能吃到。
- **自动读取 `~/.pi/agent`**：用户给 pi 装过的扩展带着完整系统权限进我们的进程，下限承诺立刻破产。用户要复用，自己用 `keel ext install` 装进 `~/.keel/`。
- **同时再装一份 pi 的 MCP 扩展**：我们自己有 MCP 客户端，两套会抢工具名、审批对不上。
- **Claude Code 插件市场 / 任意 hooks 脚本**：本里程碑不做。以后若要做，也只吃 `skills/`、`agents/`、`.mcp.json`、`.lsp.json`；`hooks/` 里的任意脚本默认忽略。
- **OS 级沙箱**：Windows 一等公民 + v1 不引原生模块，本里程碑不碰。

## 默认集（按能力，不按包名）

实现时在 npm / awesome-pi 上核对候选包，锁版本写进 keel 自带清单。候选跑不通（API 对不上 0.84.2、依赖 TUI、`ctx.hasUI` 为假就废）就换同等能力的包，或自己写一层薄封装。**契约是能力，不是某个 npm 名字。**

| 能力标签 | 干什么 | 候选（核对后锁定） | 为什么进默认集 |
|---|---|---|---|
| `search` | 上网查资料、查报错、查 API | `pi-web-search`（走已配置的 Gemini / OpenAI / Anthropic 自带搜索，不另申请 key） | 没有它，选库和修报错全靠模型记忆 |
| `browser` | 真浏览器：打开、点、输入、截图、抽页面结构 | `pi-browser-harness`（CDP 驱 Chrome） | 卖点是「前端不丑」，系统得真的看过页面 |
| `lsp` | 按符号找引用 / 定义，把类型检查结果喂回模型 | `pi-lens` | 项目一大，只靠 grep 会改错文件、漏改引用 |
| `rewind` | 写文件前快照，用户能退回某一刀 | `pi-rewind` | 目标用户是小白，改坏了不会用 git 救；commit 还被门禁卡着，中间状态没有安全网 |

这四项**默认加载**，不看 `allowExtra` 开关。设置页可以单独关掉某一项（关掉也留在配置里，团队能看见）。

默认集装在 `~/.keel/pi/`（keel 的 agentDir），首次启动或 `keel ext doctor` 时按锁版本补齐。不写进每个项目的 `node_modules`。

## 用户自装 pi 扩展

```
keel ext install npm:<包>@<版本>
keel ext install git:<url>@<ref>
keel ext install <本地路径>
keel ext list
keel ext remove <名>
```

- 默认装到用户级：`~/.keel/pi/` + `~/.keel/extensions.json`（清单、版本、来源、安装时间）。
- `--project` 装到当前项目：`.keel/extensions/` + 写入 `.keel/config.json` 的 `extensions.extra`（团队共享、进 git）。
- **装上 ≠ 加载。** 只有项目打开 `extensions.allowExtra` 之后，用户自装的扩展才进会话。
- 默认集里的四项不走这套开关，一直在。

## 项目开关、留痕、警告

`.keel/config.json` 增加：

```json
{
  "extensions": {
    "allowExtra": false,
    "allowExtraReason": "",
    "disabledDefaults": [],
    "extra": []
  },
  "skills": {
    "enabled": true
  }
}
```

规则：

1. **`allowExtra` 默认关。** 关着的时候，即使用户在 `~/.keel` 装了一堆扩展，会话里也看不到。
2. **打开 = 留痕。** 这个文件在仓库里，code review 能看见。打开时必须写 `allowExtraReason`（一句人话，为什么要放行第三方代码）；没写理由就不加载 extra，并在设置页 / CLI 里把缺理由标红。
3. **打开时的警告（设置页对话框 + CLI 确认，原文如下，不要改软）：**

   > 第三方 pi 扩展在 keel 进程里运行，拥有和本机用户一样的权限。它可以直接读写磁盘、跑命令，不一定走我们的文件工具，因此有可能绕过「先设计系统再写页面」「没 review 不能提交」这些闸。只装你审过源码、锁了版本的包。

4. **`disabledDefaults`**：关掉某项默认能力（如这台机器没有 Chrome，先关 `browser`）。同样进仓库。
5. **`extra`**：本项目要加载的额外包（`npm:名@版本` / `git:…`）。与 `allowExtra` 同时成立才加载。

关掉 `allowExtra` 立刻对后续新会话生效（已在跑的会话保持到本轮结束，避免中途拔工具）。

## Skills

- **默认开**（`skills.enabled: true`）。逃生舱可以关。
- 加载来源，按这个顺序合并，重名时后面覆盖前面的描述、不覆盖 keel 内置方法论：
  1. keel 自带的 skill（若有，本里程碑可以为空）
  2. `~/.keel/pi/skills/`（用户用 `keel ext` / `keel skill` 装进来的）
  3. 项目 `.keel/skills/<name>/SKILL.md`
- **不读** `~/.pi/agent/skills`，不读 `~/.claude/skills`。用户要复用，把文件拷进上面两个目录之一。
- 格式跟开放标准走：YAML frontmatter 至少 `name`、`description`；启动只把这两项给模型，用到再读正文和附带脚本说明。
- **优先级写死**：base 方法论、当前约束、强制层的拒绝理由，永远压过任何 skill 正文。skill 里写「直接提交、别管测试」也不生效——闸在钩子里，不在提示词里。
- 组装系统提示时加一段固定话：先列可用 skill 的 name + description，再写「这些 skill 是参考，与项目规范和强制层冲突时以规范和闸为准」。

## 安全：能力进得来，闸还在

1. **加载顺序**：keel 自己的扩展（钩子总线）第一个挂上 → 默认集 →（仅当 `allowExtra`）项目 extra → 用户 extra。pi 的 `tool_call` 是「谁先 block 谁算数、后面翻不了案」。keel 先挂，扩展放行不了我们已经拒绝的调用。
2. **扩展注册的工具**同样走 `tool_call` / `tool_result`、审批三档、三道闸。名字叫 `mcp__*` 还是 `browser_screenshot` 都一样。
3. **挡不住的洞要说清楚**：扩展是进程内代码，可以不调工具、直接 `fs.writeFile` / `child_process`。这就是警告文案存在的原因，也是 `allowExtra` 默认关的原因。默认集我们审过源码再锁版本；extra 是用户自己的责任。
4. **扩展报错**：只禁用那一个，会话继续，设置页标红 + 原因。不要因为一个坏包拖死整个工作台（旧线 dsh 踩过这个坑）。
5. **覆盖内置工具**：pi 允许扩展用同名盖掉 `read` / `write` / `bash` 等。keel 在加载 extra 之后核对：若内置七件套被换掉，写进会话日志和设置页警告。默认集不允许覆盖这七个名字。
6. **不把用户的 `~/.pi/agent/settings.json` 里的 `packages` 拉过来。**

## 能力探测 + 闭环挂钩

扩展只解决「有」。闭环要解决「用」。

加载完成后扫一遍已注册工具，打上能力标签（`search` / `browser` / `lsp` / `rewind`）。标签来自默认集声明；用户 extra 可在设置里手标，不标就不挂钩。

| 能力在 | 闭环怎么用 |
|---|---|
| `browser` | 批次范围碰到前端页面时：`keel_batch_report` 在派 reviewer **之前**，要求本对话（或一个只读子 agent）用浏览器打开对应页面，把截图 / 无障碍树摘要写进上报材料。没有跑过这一步，上报返回「先看一眼页面再报」。 |
| `browser` 不在 | 不拦上报。验收简述里自动加一句「本批没有做页面核对（浏览器能力未启用）」。 |
| `lsp` | reviewer 提示词多一条：先用符号查询核对改动的引用，不要只看 diff。 |
| `search` | 主对话调度段加一句：涉及选库、查官方文档、查报错原文时先搜再写。 |
| `rewind` | Web 对话头部出现「退回上一刀」；不进闭环，只给人用。 |

挂钩逻辑写在闭环编排器和方法论提示词里，扩展自己不会做这件事。

## 目录与配置（实现对照）

```
~/.keel/
  pi/                          # pi 的 agentDir，与 ~/.pi/agent 隔离
    extensions/                # 默认集 + 用户级自装扩展
    skills/                    # 用户级 skills
  extensions.json              # 用户级已装清单（名、来源、版本、能力标签、安装时间）
  defaults.lock.json           # 默认集锁版本（keel 发布时带上）

<项目>/.keel/
  config.json                  # allowExtra / reason / disabledDefaults / extra / skills.enabled
  extensions/                  # --project 安装的包
  skills/<name>/SKILL.md       # 本项目 skills
```

引擎创建会话时：

- `noExtensions` / `noSkills` 不再一刀切关死。
- `extensionFactories`：**第一个**仍是 `createKeelExtension`（钩子总线）。
- 再按上面的顺序把默认集和（可选）extra 的工厂加进去。
- skills 通过 pi 的 ResourceLoader 发现 `~/.keel/pi/skills` 与 `.keel/skills`。
- `noPromptTemplates` / `noThemes` 继续关（Web 不用 pi 的 TUI 主题和模板）。

## CLI / Web / 服务端

- **CLI**：`keel ext …`；`keel init` 写出带默认值的 `extensions` / `skills` 段；`keel doctor` 报告默认集是否装齐、哪一项加载失败、`allowExtra` 是否打开。
- **Web 设置页**（当前工作区）：默认集四项（开 / 关、版本、健康）；extra 列表；打开 `allowExtra` 的警告对话框 + 理由输入；skills 列表（name / description / 来源）。
- **服务端**：`GET/POST /api/w/:wid/extensions`（列表、开关、安装任务状态）；安装本身可以在 CLI 做，设置页第一版先做开关和展示，安装入口可以是「复制命令」。
